## 0. 核心认知(一开始没绕清楚的)

- **train_bpe 和 encode 是两个阶段:train = 造表(慢,离线,跑一次),encode = 查表(快,反复用)。**
  - train_bpe 统计语料、**发明**出 `vocab` + `merges`(存进 `.pkl`)。
  - encode **照着** merges 这张有序表回放,把文本切成 token id。**encode 永远不训练。**
- encode 里那个"按顺序套 merge"的循环 **不是训练**,只是读表执行规则。
- 测试用的不是我自己训的表,而是 **GPT-2 官方 vocab/merges**(`gpt2_vocab.json` / `gpt2_merges.txt`),
  目的是拿我的 encode 跟 `tiktoken` 逐个 id 对答案。我自己训的 `my_bpe_owt.pkl` 跟这道题无关。

### encode 的四步主链
1. **切 pre-token**:`re.findall(PAT, text)`(PAT 与训练时同一个正则)
2. **转字节元组**:每个 pre-token → `tuple(bytes([x]) for x in tok.encode('utf-8'))`
3. **按 merges 顺序套合并**:反复挑当前序列里 rank 最小的相邻 pair 合并,直到没有可合的
4. **查 id**:合完的每个 token bytes → `token_to_id[tok]`,按原文顺序拼成 `list[int]`

## 2. 数据结构理解模糊的地方

- **`merges` 是 list of tuple**,每个元素是 `(bytes, bytes)`。
  - `for k, v in self.merges:` 是**元组解包**,每轮把一个 tuple 拆成 `k, v`。所以看到 `merge k b' ' v b't'` 是正常的。
- **list 用整数下标索引**(`merges[0]`),**dict 用 key 索引**(`token_to_id[b'the']`)。写法都像 `x[...]` 但机制不同。
- **要"第几个"用 `enumerate`**:`for i, (k, v) in enumerate(self.merges)`,`i` 就是 rank(优先级序号,越小越先合)。
  → 我在 `__init__` 里把 merges 预处理成 `self.pair_rank_in_merges = {pair: i}`,encode 查 rank O(1)。
- **list 没有 `.contains()` 方法**,判断成员用 `pair in self.merges` / `pair in dict`。

## 3. encode 合并逻辑的关键 bug(算法核心)

### 3a. "从左到右遇到第一个能合的就合" —— 错!
BPE 规则是**按 merge rank(训练时学到的先后)合并,不是按位置**。
当一个 pre-token 里有多个可合 pair 时,要先合 **rank 最小**的那个。
→ 做法:每轮扫描当前序列所有相邻 pair,收集"在 merges 表里"的,挑 `min(ranks, key=ranks.get)`。

### 3b. `pair_rank_in_merges[pair]` 直接取值 → `KeyError`
很多相邻 pair 根本不在 merges 表里。必须**先判断 `if pair in self.pair_rank_in_merges`** 再取。
这件事和**结束条件**是一体的:一轮扫下来 `ranks` 为空 → 没得合 → break。

### 3c. 只合并了一次就停 —— `i` 没复位
```
while True:
    ranks = {}
    i = 0          # ← 这行原来在 while True 外面,导致第二轮 i 还停在大值,内层 while 直接不进
    while i < len(current_token)-1: ...
```
`i = 0` 必须放在 `while True` **里面**,保证每轮重新扫 `current_token` 都从头扫。
（每合并一次 word 至少减 1,所以循环一定会停,不会死循环。）

### 3d. 查 id 时拿**整个元组**去查 → `KeyError: (b'Hello',)`
`current_token` 是元组 `(b'Hello',)`,但 `token_to_id` 的 key 是单个 bytes `b'Hello'`。
要**遍历元组里每个 token** 分别查:`for tok in current_token: words.append(token_to_id[tok])`。
（合并完的元组可能含 1 个或多个 token,如 ` cat` → `(b' c', b'a', b't')`。）

✅ 修完后 `encode("Hello, how are you?")` = `[15496, 11, 703, 389, 345, 30]`,与 tiktoken 一致。

## 4. decode 的坑

- **缺 `decode` 方法** → `AttributeError`。
- **必须先把所有 bytes `b"".join` 拼起来再一次性 decode**,不能逐 token decode:
  一个多字节 UTF-8 字符可能被切在两个 token 里,单个 token 不是合法 UTF-8。
- **`errors="replace"`**:测试会 `decode([单个半字符 token])`(如 id 127 = `b'\xc3'`,是 `é` 的前半字节),
  默认 `errors="strict"` 会抛 `UnicodeDecodeError`。handout 要求坏字节降级成 `�`(U+FFFD)。
  - 正常 decode 整串时半字符会被 join 成完整字符,replace 不触发;只有故意拆半字符才用到兜底。**加了有益无害。**

## 5. special token 处理(encode 最容易错的一块)

**思路:encode 一进来先按 special token 切段,special 段直接映射成一个 id,只对普通段跑 BPE。**

踩的坑,按顺序:

### 5a. `re.split(flag.encode("utf-8"), text)` → `TypeError: cannot use a bytes pattern on a string-like object`
训练时 `worker` 从文件读的是 **bytes**,所以 pattern 也 encode 成 bytes;
但 encode 的 `text` 是 **str**,pattern 也得是 str。**别 `.encode()`**。

### 5b. `re.split` 默认丢掉分隔符 → special token 全没了(`chunks` 里只剩普通段和空串)
要用**捕获组** `(...)` 包住 pattern,split 才会把 special token 保留在结果里。

### 5c. `words = list()` 写在 `for chunk` 循环**里面** → 每个 chunk 清空一次,只剩最后一段(担心的"顺序乱"真相)
`words` 要在循环**外**声明,跨 chunk 累积。chunks 本身保序,顺序天然正确。

### 5d. special 段用 `words.extend(token_to_id[...])` → `'int' object is not iterable`
special 段只对应**一个 id**,用 `append`;普通段返回一串 id,才用 `extend`。

### 5e. Bug 3(最隐蔽):对每个 special token 分别 `re.split` 并覆盖 `chunks` → 只有最后一个生效
`test_overlapping_special_tokens` 暴露:`["<|endoftext|>", "<|endoftext|><|endoftext|>"]`,
循环最后一轮用"双"token split,导致中间双 token 保留、**结尾单 token 丢失**(count 0 ≠ 1)。
**正确:把所有 special token 拼成一个 alternation,只 split 一次。**

### 5f. 重叠匹配:必须**长的在前**
```
specials = sorted(self.special_tokens, key=len, reverse=True)   # 长 → 短
flag = "(" + "|".join(re.escape(s) for s in specials) + ")"
chunks = re.split(flag, text)
```
正则 alternation 从左到右试,先匹配上谁用谁。
- `(双|单)`:扫到 `<|endoftext|><|endoftext|>` 先试"双"命中整串 ✅;扫到单个先试"双"不中再试"单"命中 ✅
- `(单|双)`:会把双 token 拆成两个单的 ❌
`re.escape` + `"|".join` 自动生成正则,不用手写。

## 6. encode_iterable —— generator 与内存

测试把内存卡到 **1MB**,文件 **5MB**。不能 `f.read()` 整个读进来。

```python
def encode_iterable(self, iterable):
    for line in iterable:           # 文件逐行,一次只一行进内存
        yield from self.encode(line)  # 复用 encode,把这行的 id 一个个吐出去
```

- **`yield` 机制**:带 yield 的函数调用时不执行,返回 generator;`for`/`next` 每次推动它跑到下一个 yield 吐一个值,
  函数体跑完抛 `StopIteration` 通知 for 结束。**"拉一个算一个",内存不囤整个文件** → 过 1MB 限制。
- **`yield from xxx`** = `for v in xxx: yield v`。
- **不能 `.strip()` 掉行尾 `\n`**:`for line in f` 保留换行符,strip 掉 decode 还原会少字符,roundtrip fail。
- 逐行切分不影响正确性:PAT 本就把 `\n` 当 token 边界,行与行之间本来就不跨边界合并。
